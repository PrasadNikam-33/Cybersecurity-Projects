# RIP Configuration in Cisco Packet Tracer

## 📌 Overview

This project demonstrates the configuration of **Routing Information Protocol (RIP)** in Cisco Packet Tracer to enable communication between devices connected through multiple routers. It explains how RIP dynamically exchanges routing information and selects routes based on hop count.

## 🎯 Objectives

- Understand the fundamentals of RIP.
- Configure IP addresses on PCs, routers, and servers.
- Enable dynamic routing using RIP.
- Establish communication between different networks.
- Verify packet transmission using Cisco Packet Tracer.

## 🛠️ Tools & Technologies

- **Software:** Cisco Packet Tracer
- **Protocol:** Routing Information Protocol (RIP)
- **Devices:** 5 Routers, 1 PC, and 1 Server
- **Connections:** Ethernet and Serial DCE cables

## ⚙️ Implementation

1. Designed a network topology consisting of five routers, a PC, and a server.
2. Assigned IP addresses to the connected devices and router interfaces.
3. Added serial interfaces where required to establish router-to-router connections.
4. Configured RIP on each router by advertising its connected networks.
5. Tested end-to-end connectivity between the PC and the server.

## 📚 Key Learnings

- Dynamic routing and routing table updates.
- IP addressing and subnet-based network communication.
- RIP configuration and hop-count-based route selection.
- Troubleshooting connectivity between different networks.
- Verifying packet flow using Simulation Mode in Cisco Packet Tracer.

## ⚠️ Limitations of RIP

- Maximum supported route distance of 15 hops.
- Selects routes based on hop count rather than bandwidth.
- Slower convergence compared with modern routing protocols.
